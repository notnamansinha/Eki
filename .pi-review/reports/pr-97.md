## Summary
The PR moves the only cross-core read of TinyGPSPlus state out of the publisher task (core 0) and onto the GNSS loop task (core 1), where the checksum counter is exclusively written by `gps.encode()`. The scalar is snapshotted once per second under the existing `healthMetricsMux`, and both local (`reportHealth`) and remote (`publishRemoteDiagnostic`) reporters now consume that protected snapshot via `healthCounters()`. The race in issue #69 is structurally eliminated, not merely narrowed — the foreign core can no longer touch the TinyGPSPlus object at all. The change is minimal (one file, ~15 net lines) and follows the established protected-counter pattern; the only gap is the absence of automated test coverage for the snapshot path.
