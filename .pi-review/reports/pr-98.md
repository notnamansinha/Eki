### Lane 1 — Checksum correctness
`calculatedChecksum()` (telemetry_queue.h:180-199) is FNV-1a over all seven metadata fields (`configurationTag_`, `nextSequence_`, `overflowDrops_`, `staleDrops_`, `head_`, `count_`, `highWaterMark_`) plus the **complete** `samples_[Capacity]` array. Commit order is airtight on every mutator: `beginMutation()` zeroes `magic_` before any state change, `finishMutation()` writes `checksum_` then `magic_` last. This is exactly the `reset_stats.h` pattern (magic invalidated until checksum+fields are coherent) applied consistently to the queue. Correct: `magic_` and `checksum_` are deliberately excluded from the hash; `remove()`'s no-op path (sequence not found) correctly skips begin/finish since nothing mutated.

### Lane 2 — Magic invalidation
All four mutators (`reset`, `push`, `remove`, `dropOlderThan`) invalidate before mutating and commit after. `reset()` invalidates implicitly via `std::memset(this, 0, ...)` then `finishMutation()`. `initializeOrRecover` mutates only via `reset()`. No mutation path bypasses the guard. Reads (`newest`, `stats`, `size`) are const and, in main.cpp, always under `telemetryQueueMux` critical sections — no task can observe `magic_ == 0` mid-mutation.

### Lane 3 — Recovery path
On detection, `initializeOrRecover` falls through to `reset()` which memsets first — corrupted `head_`/`count_` are never used as indexes during reset; `calculatedChecksum()` on corrupt state is a fixed-length byte read with no indexing/branching on values (safe). Bounds restored (head_=0, count_=0), trivial construction preserved (no constructors added; class remains trivially copyable; `is_trivial<TelemetryQueue>` static_assert still passes). Magic bumped `0x...02 → 0x...03` correctly invalidates pre-PR RTC layouts (which also lack `checksum_`).

### Lane 4 — Tests
The new test deterministically corrupts one byte in the samples array, asserts `integrityIsValid()` false, `initializeOrRecover(42)` false, then valid/reset/empty. The existing purge test exercises the `dropOlderThan` commit path via `initializeOrRecover(7) == true`. Gaps are listed below (single corruption point, no positive-path-with-data preservation check, no per-field corruption).

## Verdict
APPROVE — the change is correct, consistent with the repo's existing ResetStats checksum pattern, and directly closes #70's root cause (torn RTC state passing structural validation); only minor test-coverage and documentation nits remain.

## Summary
The PR adds an FNV-1a checksum over all queue metadata plus the full fixed sample array, invalidates the queue magic before every mutation and restores it only after checksum commit, and gates `initializeOrRecover` on the checksum so any torn or corrupted RTC state is rejected and reset. This fixes the #70 root cause: previously, a mid-mutation power loss could leave structurally-plausible but inconsistent RTC metadata that passed `initializeOrRecover`'s field checks. The change is minimal, preserves trivial construction and the 6 KiB RTC bound (struct size unchanged due to trailing alignment padding), and adds one corruption-recovery test plus integrity assertions on the existing mutators.

## Test assessment
The new test correctly mutates (single byte flip in the samples array), verifies detection (`integrityIsValid()` false), verifies recovery (returns false, then valid/empty after reset). Commit order is covered on all mutators: reset/push/remove via explicit `integrityIsValid()` assertions, dropOlderThan indirectly via `initializeOrRecover(7) == true` in `test_queue_purges_stale_samples_and_validates_rtc_identity`. `test_queue_wraparound` exercises the eraseAt middle-shift and O(1) head-removal paths but adds no integrity assertion (remove is covered in the first test). Missing: per-field and per-structural-violation corruption cases, checksum-only corruption, positive-path data preservation through recovery, and post-recovery functional assertions. All test outcomes are deterministic (no flake risk).

## Security assessment
No new external inputs, secrets, or authorization surfaces are introduced; the checksum is a data-integrity guard, not a security control. The design fails closed: any state that does not satisfy magic + structural bounds + checksum is discarded and re-initialized, and corrupted indexes are never used during recovery (`reset()` memsets before any field access). Buffer bounds remain enforced by the pre-existing `initializeOrRecover` structural checks plus the Capacity static_asserts; no new indexing code was added.

## Residual risks
- Runtime (post-boot) RTC corruption is only detected at the next boot — `initializeOrRecover` is the sole integrity gate. A mid-mutation brownout that does not reboot could leave a torn sample served once at runtime; the next mutation self-heals the checksum. Pre-existing risk class, outside #70's scope, but worth noting.
- The magic bump (0x…02 → 0x…03) deliberately discards all pre-PR RTC queue state once; the first boot after upgrade will log "initialized" instead of "recovered" — expected, but confirm operators aren't surprised by the one-time queue loss.
- Per-mutation hashing of up to ~5.8 KiB of RTC slow memory inside a critical section: negligible at 1 Hz fix rates, but watch the publisher path (`dropOlderThan` + `newest` under mux) for timing impact if fix rates or capacity increase.
- The new test's corruption point depends on struct layout; it will still pass if the layout changes, but its stated intent (samples-array corruption) could silently become metadata corruption.
