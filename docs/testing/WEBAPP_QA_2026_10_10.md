## Developer diagnostics and optimization

Fresh live admin, passenger and fixture browser logs contained no captured errors/warnings in the inspected windows. The older admin tab retained a historical Firestore listen transport warning; subsequent data loaded. This does not prove an absence of all network failures.

The standalone feedback page statically imported the full panel, including its database dependencies. It now uses a client-side dynamic import with an accessible loading status, consistent with admin panel loading. The enclosing admin RoleGuard remains unchanged. The panel loads after authorization mounts its child; authenticated users still download the panel when they open it.

Production HTML bootstrap references were deduplicated and their local JS/CSS files measured. Gzip values are estimates using Node gzip, not captured transferred bytes.

| Metric | Before | After |
| --- | ---: | ---: |
| Feedback bootstrap JS/CSS | 1,413.4 KiB | 669.7 KiB |
| Feedback bootstrap gzip estimate | 417.5 KiB | 198.1 KiB |

| Landing bootstrap | 668.5 KiB | 668.5 KiB |

| Passenger bootstrap | 669.6 KiB | 669.6 KiB |

This removes about 53% of feedback bootstrap bytes and 41% of precache bytes. It defers panel code; it does not claim a 53% reduction in complete authenticated page traffic or elapsed load time. CSP inline hashes were regenerated with the local backend origin retained and the contract verified.

The available browser diagnostics exposed console logs and DOM/layout inspection, but not the native DevTools Network/Performance panels or a usable performance timing API. No Lighthouse score, LCP, INP, CLS, memory plateau, frame-rate, or network waterfall measurement is claimed. Those require a separate production-runtime profiling run before calling performance optimal.
